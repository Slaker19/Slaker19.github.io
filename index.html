AOOSTAR WTR PRO: Nodo Silencioso (15W)

Mi servidor bare-metal personal de producción corre ininterrumpidamente sobre un chasis compacto NAS de 4 bahías, optimizado para máxima densidad de cálculo y consumo mínimo.

AMD Ryzen 7 5825U

Zen 3 Barcelo · 8 Cores / 16 Threads · 15W TDP

El corazón del nodo es un procesador de 8 núcleos y 16 hilos con arquitectura Zen 3 de 7nm. Proporciona una densidad de cálculo excepcional manteniendo el nodo en un consumo en reposo de solo 12W-15W.

  • Frecuencia Base / Boost2.0 GHz / 4.5 GHz
  • Caché L316 MB Unified
  • VirtualizaciónAMD-V con soporte IOMMU/VFIO
  • Gráficos IntegradosAMD Radeon Vega 8 (GPGPU/HW Transcoding)
  • Gobernador CPUschedutil (escalado adaptativo)

Dual NVMe Linux RAID 0

Array de Alto Rendimiento `/dev/md0` · 1.8 TB

Dos unidades NVMe M.2 PCIe 3.0 de 1 TB configuradas en striping RAID 0 mediante el kernel Linux (`mdraid`). Ofrece un ancho de banda de más de 3.5 GB/s para operaciones intensivas de I/O de máquinas virtuales.

  • Dispositivos Miembro/dev/nvme0n1 (1TB) + /dev/nvme1n1 (1TB)
  • Punto de Montaje/mnt/raid0 (ext4, discard, noatime)
  • Chunk Size512 KB Striping
  • Uso PrincipalDiscos VM QCOW2, contenedores y scratch
  • Monitorizaciónsysfs en tiempo real (/sys/block/md0/md)

Dual 2.5 GbE Intel I226-V

Multi-Gigabit L2 Microsegmentation & Bridges

Doble interfaz Ethernet Intel I226-V de 2.5 Gbps que permite separar físicamente el tráfico de administración del uplink de alta velocidad para VMs y almacenamiento en red.

  • Controladora eth0Intel I226-V (2.5 Gbps) · Uplink LAN vmbr0
  • Controladora eth1Intel I226-V (2.5 Gbps) · Direct Storage Link
  • TopologíaBridge físico compartido L2 (sin doble NAT)
  • CortafuegosFiltrado nativo por nftables en el kernel
  • AislamientoVLAN tagging y subredes seguras

Chasis Híbrido 4 Bahías SATA

Factor de Forma NAS Compacto con Bahías Hot-Swap

Chasis de aleación de aluminio con 4 bahías frontales hot-swap SATA de 3.5"/2.5", complementado con ranuras M.2 internas para separación de capas calientes y frías de datos.

  • Bahía 1 (SO)512 GB Btrfs SSD (Host OS & Logs)
  • Bahía 2 (Backup)3 TB SATA Btrfs (Instantáneas y Backups)
  • Bahías 3 y 4Expansión disponible para almacenamiento masivo
  • RefrigeraciónVentilador de levitación magnética PWM
  • Ruido Operativo< 22 dB (Silencioso en 24/7)

KVM VMs + Contenedores Incus/LXC unificados

A diferencia de Proxmox que exige tomar el control total del servidor, WebKVM se ejecuta como un simple servicio systemd no invasivo.

  • Máquinas virtuales KVM completas para Windows, Linux y BSD con QEMU.
  • Contenedores de sistema Incus/LXC ultra rápidos que arrancan en < 1 segundo.
  • Consolas gráficas noVNC y terminales PTY serial acelerados por WebGL (xterm.js).
  • Telemetría reactiva en tiempo real mediante Server-Sent Events (SSE).

Gestión de Software RAID Nativa por Kernel sysfs

En lugar de ejecutar procesos hijos `mdadm` en bucles lentos, WebKVM lee directamente el subsistema del kernel Linux en `/sys/block/md*/md`.

  • Descubrimiento en tiempo real sin sobrecarga de subprocesos.
  • Formateo automático (ext4, xfs, btrfs) y unidades de montaje persistentes systemd.
  • Aprovisionamiento de storage pools en 1 clic sobre el array recién creado.
  • Montaje no destructivo de arrays existentes y monitorización de scrub/sync en vivo.
// ParseArrayState: lectura directa de sysfs del kernel func readSysfsArray(name string) (*RAIDState, error) { base := filepath.Join("/sys/block", name, "md") level, _ := os.ReadFile(filepath.Join(base, "level")) syncAction, _ := os.ReadFile(filepath.Join(base, "sync_action")) degraded, _ := os.ReadFile(filepath.Join(base, "degraded")) return &RAIDState{ Level: strings.TrimSpace(string(level)), SyncAction: strings.TrimSpace(string(syncAction)), Degraded: strings.TrimSpace(string(degraded)) != "0", }, nil }

Seguridad Defensiva y CLI Zero-Token

Diseñado con arquitectura de confianza cero en los límites de red y control de acceso riguroso para entornos de producción.

  • Tickets efímeros en RAM de 30 segundos para WebSockets (cero JWTs expuestos en URLs).
  • Dialer anti-SSRF con bloqueo estricto de rangos privados, CGNAT y loopback en descargas de imágenes.
  • Ventana de confirmación de 30s con auto-rollback en reglas de firewall.
  • CLI autónomo (`webkvm-cli`) con acceso zero-token como root y autodetección del listener.
