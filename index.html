    Rendimiento antes que abstracción

    Si el kernel ya lo resuelve —sysfs, namespaces, cgroups v2, nftables— no hace falta un daemon extra. Cada capa que añado tiene que justificar su coste en RAM, CPU y superficie de fallo.

    El hardware también es parte del trabajo

    KVM e Incus detrás de la misma interfaz

    Un backend desacoplado decide qué motor ejecuta cada instancia. La UI no sabe si detrás hay QEMU o un contenedor LXC.

    • VM completas con QEMU, OVMF y swtpm
    • Contenedores Incus que arrancan en menos de un segundo
    • Consola noVNC y terminal serie en el navegador
    • Telemetría por SSE, sin polling

    El estado del RAID se lee del kernel

    Sin lanzar mdadm en bucle. WebKVM lee /sys/block/md*/md y muestra el array tal y como lo ve el kernel.

    • Descubrimiento sin subprocesos
    • Formateo y montaje persistente en un paso
    • Montaje no destructivo de arrays existentes
    • Estado de sync y degradado en vivo
    // lectura directa de sysfs
func readArray(name string) (*State, error) {
  base := filepath.Join("/sys/block", name, "md")
  level, _ := os.ReadFile(filepath.Join(base, "level"))
  sync, _ := os.ReadFile(filepath.Join(base, "sync_action"))

  return &State{
    Level:  strings.TrimSpace(string(level)),
    Sync:   strings.TrimSpace(string(sync)),
  }, nil
}

    Superficie mínima, decisiones explícitas

    Cada límite de confianza está escrito en el código: cookies, tickets de WebSocket y descargas de imágenes.

    • Cookies sin flag Secure cuando el TLS está desactivado
    • Tickets efímeros de 30 s para WebSocket
    • Dialer anti-SSRF en descargas de imágenes
    • CLI local sin tokens, leyendo la clave del host
    // issue #5: no romper el login en HTTP plano
func cookiesSecure(cfg bool, mode TLSMode, env bool) bool {
  if mode == tlsOff && !env {
    return false
  }
  return cfg
}
